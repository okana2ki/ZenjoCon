# 全情コン応募支援を体験しよう

このフォルダは、Codexに自分のアイデアを読んでもらい、講評をファイルに残してもらうための教材です。今日の目標は、AIによる講評を読んで、自分で一か所改善するところまでです。応募用紙の完成は授業後に進められます。

## AIと自分の役割
| AIがすること | 自分がすること |
| --- | --- |
| メモと審査基準を読む | 身近な困りごとを選び、メモを書く |
| 良い点・不明点・確かめ方を整理する | 助言の採用・見送り・保留を決める |
| 講評と参照時のメモ控えを保存する | 自分の言葉で修正し、内容に責任を持つ |
| 記入された応募用紙を読んで講評する | 応募用紙に記入する |

AIに応募原稿を代筆させないのは、この授業の方針です。AIの助言を見送ることもできます。もっともらしい回答でも、事実や根拠を自分で確認しましょう。

## 始める前に
1. 配られたフォルダ`ZenjoCon-main`を自分のPCの授業用の場所にコピーします。ほかの授業の大切なファイルと混ぜません。
2. Codexプロジェクトのソースフォルダに、このREADMEとAGENTS.mdがある「全情コン応募支援」フォルダを指定します。
3. 講師の指示に従い、授業用フォルダへの書き込みができる設定を確認します。フルアクセスは使いません。
4. 氏名、連絡先、顔写真などはメモに入れません。「生徒A」「利用者」などで十分です。ローカルファイルでも、AIに読ませる内容として学校のルールを守ります。

AGENTS.mdはAIへの行動指示です。ファイルごとの編集禁止を技術的に保証するものではありません。配布原本は別に残し、各自のコピーをプロジェクトのソースフォルダにします。

## 1. 自分でメモを書く（約7分）
[アイデアメモ](student/アイデアメモ.md)をメモ帳などで開き、5項目を短く書いて保存します。全体で300〜800字程度を目安に、箇条書きでも構いません。まだ分からないところは「未確認」と書けます。
題材が決まらない場合は、[練習用アイデア](examples/練習用アイデア.md)を使えます。この例は架空です。

## 2. Codexに講評を依頼する（約8分）
プロジェクト内で新しいチャットを開き、次を送ります。

> AGENTS.mdに従って、student/アイデアメモ.mdを読み、審査基準に照らして良い点・不足している点・次に確かめることを整理してください。応募文章は書かず、feedback/に講評と参照したメモの控えを新規保存してください。作成したファイルを教えてください。

AIの作業表示で、何を読んだか、何を作ったかを確認します。終わったらfeedback/の講評を開きます。AIの控えは確認用で、応募原稿ではありません。

練習例を使う場合は、依頼文の student/アイデアメモ.md を examples/練習用アイデア.md に置き換えます。練習結果を自分の実績にしないでください。

## 3. 自分で判断し、修正する（約10分）
[判断と振り返り](student/判断と振り返り.md)に、助言を採用するかどうかとその理由を書きます。すべて採用する必要はありません。
自分のアイデアメモを、自分の言葉で一か所以上修正します。未実施の調査を「実施した」と書かず、これから行う計画として記録します。

## 4. 再講評を依頼する（約7分）
メモと判断記録を保存してから、先ほどのチャットの続きとして、次を書いて送信します。

> 修正したstudent/アイデアメモ.mdとstudent/判断と振り返り.mdを、直前の講評・メモ控えと比べてください。明確になったことと、まだ確かめることを中心に再講評し、feedback/に新しい番号で保存してください。見送った助言も尊重し、応募文章は書かないでください。

新しい講評を読んで、自分の修正がどう受け取られたかを確認します。今日の授業後半でのAIへの依頼は、原則この2回です。

## 5. 振り返る（約4分）
判断記録の最後に、AIがファイルを操作した場面、AIの助言に疑問を持った点、自分が決めたことを書きます。

## うまくいかないとき
- ファイルが読めない：指定したプロジェクトとフォルダを確認し、メモを保存しているか確かめます。
- 書き込みできない：フルアクセスに切り替えず、講師に相談します。チャットに表示された講評を読んでも活動できます。
- 利用制限・接続不良：[練習用講評](examples/練習用講評.md)を使って、どの助言を採用するか考えます。続けられるようになったらメモから再開できます。
- AIが原稿を書いた／事実を補った：その部分を応募文に使わず、根拠を確認します。講師に知らせ、「完成文ではなく質問・確かめ方を示して」と伝えます。

無料利用の提供状況や上限は変わります。短い教材でも、授業中の利用を保証するものではありません。課金やAPIキーの設定はこの演習には不要です。

## 授業のあと
応募を考える人は、応募用紙`knowledge/zenjyocon_entry_sheet_2026.pptx`中に書かれた留意事項を見ながら、自分で応募用紙を埋めます。講評ファイルやアイディアメモだけでは、正式な応募書類にはなりません。
締切・資格・最新の用紙・提出形式を[公式サイト](https://zenjyocon.jp/contest2026)で確認し、講師・保護者と進めてください。AIの利用内容は実際に行ったことを記録します。
応募書類に記入し、student/ に置いたら、それに対する講評をCodexに依頼できます。

> AGENTS.mdに従って、student/応募書類案.pptxを読み、審査基準に照らして良い点・不足している点・次に確かめることを整理してください。応募文章は書かず、feedback/に講評と参照した応募書類案を新規保存してください。作成したファイルを教えてください。

## このフォルダの構成
- AGENTS.md：AIの役割と、AIが作業する際に従う規則を記載。
- knowledge/：講師がAIと相談しながら事前にまとめたコンテストについての簡潔な資料。必要な分だけAIが読み、読んだ内容に基づいてあなたを支援します。留意事項が入った応募用紙もここに入っています。
- student/：自分が書くファイル。
- feedback/：AIが新しいファイルを作る場所。
- examples/：架空の練習教材。

別のコンテストでも「公式資料を確認して短くまとめる → AIの役割を決める → 自分のメモを講評してもらう」という構成が使えます。地方創生コンテストでは、審査基準などを専用のものに替え、データの地域・時期・指標・出典も記録してください。
